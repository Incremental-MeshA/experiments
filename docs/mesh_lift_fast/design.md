# Упрощение Lift без изменения задачи

Предыдущая версия зафиксирована в 49b1df9. Её исходники и результаты остаются
неизменными; оптимизированный код находится в cpp/mesh_lift_fast.

## Перевзвешивание не требуется

У исходного prefix-mesh внутренние дуги имеют стоимость 0, а завершение
примитива оплачивает его положительную исходную стоимость. Подграф нулевых
дуг ацикличен. Поэтому любой цикл полного графа имеет положительную стоимость.
A* и обратный ремонт допускают неотрицательные стоимости. В tight-политике
нулевые шаги продвигаются по DAG, а переход через положительное завершение
строго уменьшает h: цикла в ней быть не может. Потенциал для этого не нужен.

Новый Index читает исходные Config/Edge непосредственно из Model. У него одна
стоимость дуги: исходная, включая нули. Не создаются положительный, сжатый,
обратный и граничный шаблоны. На входе один раз проверяется ацикличность нулевых
дуг. Конфигурационный граф и ID примитивов сохраняются полностью.

Есть влияние на порядок поиска. При точной арифметике старые значения
удовлетворяли g'=g+phi и h'=h-phi, так что f'=g+h. Но второй ключ -g'
предпочитал большие g+phi, то есть в том числе глубокие префиксы. Поэтому
простое удаление потенциала меняет tie-breaking. В эксперименте zero-only
сохраняет ключ (f,-g,sequence), а fast использует (f,-g,-depth,sequence).
Последний вариант явно предпочитает глубину при равных f и g; он не объявляется
побитовым воспроизведением прежнего смешанного ключа. Для него есть отдельная
абляция без depth. Кроме того, исчезает численное сложение/вычитание потенциала.

## Что ещё убрано

- Проверка пустой политики больше не создаёт vector и не выделяет память
  на каждой извлекаемой вершине. Для существующей политики переиспользуется
  один буфер; memo сохраняет проверку общих суффиксов за один запрос.
- CLOSED переиспользуется между запросами. После адаптивного обновления он
  компактифицируется на месте и сам служит стеком closure: дополнительных
  копий CLOSED и отдельного стека нет.
- В closure попадают только действительно поднятые метки. В plain Lift нужны
  поднятые отсечённые узлы; в Cascade добавляются остальные поднятые CLOSED,
  чтобы зарегистрировать новые нарушения на заблокированных дугах.
- Отдельного флага learned нет: повышенная метка определяется по h > base.
  Это сохраняет участие поднятых без поиска узлов в обратном ремонте.
- В repair исходная оценка base берётся из записи состояния, а не вычисляется
  заново через min и hypot при каждом понижении h. Она неизменна при фиксированной
  цели и изменениях занятости карты. Численный clamp до base сохранён.
- Ключ состояния в hash map — целое (linear_cell * configurations + cfg).
  Для внешних клеток lookup немедленно возвращает отсутствие; смешивания
  трёх координат в горячем цикле нет. Переполнение ключа проверяется.
- Обратная дуга хранит свой slot: поиск std::find по исходящим дугам не нужен.
  В ремонтной очереди хранятся (h,id), без копии State и без phi.
- У h одинаковые конечные клетки объединены с минимальной стоимостью. У
  терминального отсечения сохранены все различные конечные направления,
  но клетка для них проверяется один раз. Ненужные finals граничных узлов
  вообще не материализуются в новом индексе.
- Проверки инвариантов принимают const char*: std::string сообщения
  создаётся только при ошибке. Раньше длинные сообщения могли выделять
  память даже на успешной проверке в горячем цикле. Все проверки сохранены.
- Хеш порядка извлечения не вычисляется в основном fast-варианте; отдельная
  trace-абляция позволяет измерить цену этой диагностической операции.

Это инженерные оптимизации, а не новые заявления о литературном приоритете.
Изменение порядка равностоимостных путей в навигации может изменить наблюдения.

## Почему можно сузить closure

После успешного поиска с ценой C метки CLOSED повышаются до max(h,C-g).
Для обычного раскрытого u свободный ребёнок v либо тоже CLOSED с
h(v)>=C-g(v)>=C-g(u)-c(u,v), либо остаётся в OPEN с f(v)>=C и
h(v)>=C-g(v)>=C-g(u)-c(u,v). Поэтому новое свободное нарушение может возникнуть
только у отсечённого узла. Если h(u) вообще не выросла, все её свободные
неравенства уже были выполнены; повышение правых частей их не нарушает.

У Cascade при росте h(u) нужно также проверить заблокированные дуги и подписать
нарушенные неравенства. Поэтому только для него остаются seeds из поднятых
обычных CLOSED. Старые лишние подписки безопасны. В стеке нет необходимости
поддерживать отдельную топологическую очередь: он распространяет только
нарушенные оценки по конечному DAG и сохраняет тот же инвариант согласованности.

Флаг learned не нужен при сохранении initial: если h(u)=initial(u),
согласованность initial и h(v)>=initial(v) дают h(u)<=c(u,v)+h(v).
Такой предшественник не нуждается в понижении. Уменьшившийся до initial
узел всё равно обрабатывается в очереди для распространения изменения назад.

Нельзя удалять само восстановление h или исключать поднятые без поиска
вершины из обратного ремонта. На прежнем формальном примере оба новых режима возвращают оптимум 4;
удаление этих действий давало допустимый, но подоптимальный путь 5.

## Проверяемость

Сопоставляются исходные weighted Lift, zero-only и полный fast, а компоненты
fast отключаются по одному на отдельной повторной панели. Абляции одинакового
приоритета дополнительно проверяются на идентичность путей и числа раскрытий.
Сохранены прямой primitive Dijkstra, проверка свободных неравенств, полноты
подписок, нижней границы h >= base, cap/recovery и ASan/UBSan. Нулевой цикл вне класса
prefix-графов отвергается явно. Старые результаты не смешиваются с новыми.
