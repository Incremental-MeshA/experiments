# Артефакт аудита Lift

Ветка: `perf/lift-zero-cost`. Базовая версия: `49b1df9`.
Измеренный код и протокол зафиксированы в `85fb706` до начала экспериментов.
Последующие изменения относятся к анализу, оформлению и сохранению результатов.

- [Отчёт PDF](report.pdf) и [Markdown](report.md).
- [Обоснование упрощений](design.md).
- [C++ и команды воспроизведения](../../cpp/mesh_lift_fast/README.md).
- [Замороженный протокол](../../cpp/mesh_lift_fast/frozen/manifest.json).
- [Исходные результаты](../../cpp/mesh_lift_fast/results/full/experiment.json).
- [Проверка артефакта](../../cpp/mesh_lift_fast/validation/final.json).

На 46 общих завершённых car16 replay-конфигурациях из 48: full / repair
ускорение к прежнему Lift — 1.65 / 1.91, к прежнему Cascade — 1.45 / 1.67.
Удаление только потенциала почти нейтрально по времени. Пакет уменьшает
число выделений внутри ремонта примерно в 6.3 раза; peak рабочей памяти
увеличивается примерно на 5%. Два replay-случая по-прежнему достигают лимита.
Преимущества над Batch-MPGAA* зависят от карты; полный разбор сохранён в отчёте.

Выполнено 3 348 временных эпизодов, 1 116 эпизодов памяти и отдельный
микробенчмарк построения индексов. Все 18 567 строк обычного и профилировочного
прогонов совпали по логическим полям; завершённые стоимости не расходятся
с точным эталоном. Независимые тесты: 9 640 сравнений, ASan/UBSan для обеих
моделей, детерминированный пример ремонта после освобождений.

Опциональный `introduction-lift-zero-cost.bundle` является дополнением к
репозиторию, уже содержащему `49b1df9`. Его можно импортировать так:

```bash
git fetch /path/to/introduction-lift-zero-cost.bundle perf/lift-zero-cost:perf/lift-zero-cost
git switch perf/lift-zero-cost
```

Для нового измерения следует использовать свежие каталоги результатов,
как показано в README. Предыдущие алгоритмы и их исходные результаты сохранены.
