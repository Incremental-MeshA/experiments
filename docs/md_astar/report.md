## Аннотация

В репозиторий перенесён MD-A\* — планировщик с сертификатом покрытой клетки, ограниченной рабочей картой и очередью отложенных освобождений. Реализация написана на Python и использует исходные car16, float-стоимости и карты проекта. Она сравнивается со всеми шестью основными алгоритмами репозитория и с тем же MPGAA\*, который служит её базовым поиском. Ускорение MD-A\* относительно MPGAA\*: исходные задачи — 0.98 [0.97; 1.00]×; смешанные обновления — 1.02 [0.99; 1.02]×; новый seed — 1.00×; диагностическая семья — 144.08×. На 40 эпизодах (280 записях «эпизод, запрос») выполнено 1032 запусков и 7656 измеренных вызовов. Независимый Дейкстра проверил 1458 ответов; оба новых планировщика дополнительно проверены на всех 561 исходных запросах. Выводы о выгоде оболочки отделены от преимуществ самого MPGAA\*, а прежние C++-времена не используются.

## 1. Что именно добавлено

Новая ветка основана на актуальной default-ветке репозитория, commit `cc58898`. `mesha/deferred.py` реализует MD-A\*, `mesha/adaptive.py` — независимый порт MPGAA\* (Hernández, Asín, Baier, AAAI 2015, алгоритмы 1–2). Порт использует явных предшественников ориентированных примитивов, группировку swept-cell зависимостей и консервативную рамку всех когда-либо раскрытых источников. Оболочка и отдельный MPGAA\*-контроль используют **один класс**, поэтому их прямое сравнение выделяет новый механизм.

MD-A\* сохраняет фактическую карту и рабочий подграф. Освобождённая клетка может оставаться занятой в рабочей карте, пока не способна улучшить известный допустимый путь. При повреждении маршрута верхняя граница растёт, и старые исключения пересматриваются. При неизвестной достижимости включаются все отложенные клетки. Математически достаточно нуля, одного или двух вызовов базового точного поиска. Состояния цели фиксированы на протяжении эпизода.

Это поиск по **граничным состояниям mesh с полными примитивами как макрорёбрами**. Внутренний mesh компилирует сертификат. MD-A\* не поддерживает метки всех регулярных расширенных клеток, как исходный D\* Lite (mesh). Эти два подхода решают одну дискретную задачу, но выполняют раскрытия разного типа.

Добавлен API `replan(start, new_blocks, new_opens=())`. В D\* Lite при открытиях сбрасывается кеш затронутых рёбер и обновляются также ранее неизвестные источники: ограничение лишь вершинами g/rhs было безопасно для увеличений, но пропускало бы восстановление связности. Для увеличений прежний фильтр сохранён. Дополнительные флаги `search()` исключают визуализационные списки раскрытий и полную трассу, сохраняя возврат состояний и примитивов. Старые вызовы и значения по умолчанию совместимы. Исходные данные и опубликованные результаты репозитория сохранены.

## 2. Сертификат и корректность

Для примитива p со стоимостью $C_p$, смещением $\Delta_p$ и покрытыми клетками $T_p$ выбираем октильную норму $D=\alpha d_8$ так, чтобы $D(0,\Delta_p)\le C_p$. Поправка и нижняя оценка имеют вид

$$m=\min_{p,d\in T_p}[C_p-D(0,d)-D(0,\Delta_p-d)],\qquad L_q(s,t)=D(s,q)+D(q,t)+m.$$

Два неравенства треугольника показывают: любой путь, покрывающий q, стоит не меньше $L_q$. Поправка необходима: кривая покрывает клетку, не обязательно проходя через её центр. Норма представляется максимумом восьми опорных функций; 64 префиксно-суффиксных коэффициента считаются топологическими проходами DAG одного примитива. Терминальные рёбра направляются в отдельные стоки, а не в следующий примитив. Основной запрос использует один скаляр m; MD-64 — усиленную оценку из 64 чисел. Скаляр m можно получить и прямым перебором примитивов: необходимость mesh для самой допустимости этой оценки не заявляется.

Если все ещё скрытые свободные клетки имеют $L_q\ge U$, оптимальный рабочий путь стоимости U оптимален фактически: более дешёвый путь либо содержался бы в рабочем графе, либо покрывал бы исключённую клетку. При допустимом старом суффиксе включаем потенциально полезные клетки и его собственные скрытые клетки, затем достаточно одного поиска. Если суффикса нет, первый рабочий поиск даёт $U_0$; после включения клеток с $L_q<U_0$ второй поиск даёт $U_1\le U_0$, так что остальные исключения остаются верными. При $U_0=\infty$ включаются все.

Чтобы не пересматривать историю при каждом движении, храним ключ $k_q=L_q(s_i,t)+A_i$, где A — накопленная сумма геометрических перемещений старта. Липшицевость $|L_q(s,t)-L_q(s',t)|\le D(s,s')$ даёт $k_q-A_j\le L_q(s_j,t)$. Достаточно извлекать и уточнять ключи ниже порога $U+A_j$. Возврат старта назад безопасен; может возрасти только работа уточнения.

В нативной модели 284 примитива и 412 конфигураций; $\alpha=0.926209683$, $m\approx-0.438205819$. Стоимости не квантуются. Сравнения консервативны относительно EPS проекта; совпадение ответов проверяется с допуском $10^{-6}$. Теорема дана для идеальной арифметики; float-код не выдаётся за формально верифицированный численный сертификат. Полное доказательство и численные оговорки: [method.md](method.md).

## 3. Протокол сравнения

Сравниваются LBA\*, LazyLBA\*, MeshA\*, Mesh/ParallA\*, D\* Lite на решётке и mesh-графе, MPGAA\* и MD-A\*. Все реализации — Python, все используют одинаковый `car16`, стоимость и supercover. Вес равен 1. Mesh/ParallA\* имеет мягкое отсечение дубликатов и остаётся приближённым контролем; его скорость не считается выигрышем точного поиска без учёта стоимости.

Чистый Mesh/PruningA* — неполный подалгоритм Mesh/ParallA\*, а не отдельный точный контроль. Взвешенные варианты w>1 в этой фазе не измеряются.

Исходный набор — 24 эпизода: по шести квантилям длины пар клеток на каждой из четырёх карт (Berlin_2_256, AR0700SR, maze, rooms). Одна пара курсов из каждой группы выбирается по детерминированной чётности карты/страты. Выбор зафиксирован до времён MD-A\*. Каждый эпизод содержит три запроса, два из которых гарантированно ломают маршрут. Для корректности используется весь исходный набор из 187 эпизодов, а не только временная выборка.

Дополнение: восемь смешанных эпизодов на тех же четырёх картах (фиксированный старт и возвраты), по 13 запросов, seed 761116. Квадрат 3×3 перемещается, освобождая старые клетки; раз в четыре события он размещается на текущем контрольном пути. Четыре эпизода с seed 761117 проверяют перенос на новые запросы той же коллекции карт. Непроходимые снимки не отбрасываются. Движение задаётся контрольным поиском, а не кандидатом.

Диагностика — четыре эпизода на пустых картах 80×80 и 160×160: диагональный запрос, удалённые перемещения квадрата внутри большой рамки поискового состояния, неподвижный или возвращающийся старт. Семья выбрана для проверки механизма и не является оценкой среднего выигрыша на произвольной карте.

Среда: Python 3.12.14, NumPy 2.3.5, AMD EPYC 9V74 80-Core Processor. Три повторения, последовательно, порядок методов перемешан для каждого эпизода. Таймер включает применение изменений, поиск и извлечение состояний/примитивов. Независимая проверка пути находится за таймером и не прогревает кеши планировщика. Счётчики и стоимости должны совпадать между повторениями. Общая неизменяемая модель готовится заранее, как в проекте; конструкторы планировщиков измерены отдельно. Компилятор сертификата потребовал 8.25 мс; дополнительно приводится консервативная метрика, добавляющая эту цену один раз на эпизод MD-A\*.

Метрика ускорения: отношение времени контроля к времени кандидата. Сначала суммируем нужные запросы эпизода, затем берём медиану трёх повторений и медиану парных отношений по эпизодам. Интервалы — описательная 95% перевыборка четырёх кластеров-карт (6000 выборок), не предположение независимости запросов. На новом seed и диагностической семье интервалы не приводятся. Снимки означают записи «эпизод, запрос»; некоторые парные эпизоды имеют совпадающие начальные запросы.

В первом проходе обнаружилось, что D\* Lite применял прежний лимит 3 млн раскрытий накопительно к 13 запросам. Протокол исправлен на 3 млн на запрос. Сохранены только 21 целиком законченный эпизод, в котором прежний ограничитель никогда не срабатывал; все неполные эпизоды повторены целиком. В одной паре не смешиваются фазы. Точный diff подтверждает, что изменилось только присваивание ограничителя вне таймера; код алгоритмов и среда не менялись. Исходный проход, журнал отказа и все его исходники сохранены в `development/cumulative-budget-v1`, а IDs фаз — в environment и CSV.

## 5. Корректность и воспроизводимость

Независимый Дейкстра проверил 308 снимков и 1458 ответов: car16 и legacy8, все курсы, разрез и повторное соединение компонент, повторные правки, блокировка концов для новых планировщиков, возвраты старта и 160 обновлений для очистки старых элементов кучи. Важный тест: стоимости $13 \to 13 \to 19$ при рабочем обходе 23 и реактивации старого открытия; проверены именно два вызова MPGAA\*. Все коэффициенты сверены с прямым перебором, для каждого набора проверено 128 случайных геометрических троек.

На всех 187 исходных эпизодах оба новых планировщика дали 1122 совпадающих со старым точным LBA\* ответов и столько же допустимых траекторий. Здесь старые записи используются только как стоимостной эталон. Исходный selfcheck проекта также прошёл. В измерительной фазе каждый возвращённый путь дополнительно проверен по всем покрытым клеткам и конечному курсу; точные методы совпали с контрольной стоимостью. Приближённый Mesh/ParallA\* оценивается отдельно.

| Новизна | Конкретная гипотеза, внешний приоритет не подтверждён | Mesh-компиляция клеточного сертификата и переносимая очередь известного уменьшения; сам A\*/MPGAA\*/кеш пути известны. |
| Общее преимущество | Определяется результатами раздела 4 | Целевой режим нельзя переносить на гарантированные поломки маршрута. |
| Готовность к ведущей конференции | Исследовательский артефакт, не готовая SOTA-заявка | Четыре основные карты, один основной control set, временная выборка 24 исходных эпизодов и небольшой новый seed. |

**Связь с предыдущим C++-артефактом.** Предыдущая C++-работа использовала другие примитивы, целые стоимости и другие нагрузки. Её 112× относятся к специально выделенной диагностике, а не к исходным задачам этого репозитория. Они сохранены в [справочном артефакте](reference/README.md), но не выданы за нативное воспроизведение. Новый набор отделяет проверку всего корпуса от дорогого временного поднабора и не раздувает число независимых задач повторениями/алгоритмами.

**Ограничения остаются.** Исходная постановка — только добавление препятствий на маршруте. В ней идея отсрочки освобождений почти не используется; расширенная смешанная задача является отдельным экспериментом. Для публикации нужны более широкие карты и control set, длинные серии, сравнение с DPA\*/L-GLS и независимыми оптимизированными реализациями, раздельные абляции рабочего графа и самого сертификата, более сильная численная гарантия. Коллизии здесь — дешёвые чтения 2D-сетки точечного агента, а не измерение реального контура/3D. Пиковая память не измерялась; дополнительная рабочая карта и история освобождений требуют памяти. Цель фиксирована. При разрушении маршрута два базовых поиска могут быть дороже одного; история перемещений может ослабить ключи и потребовать массового уточнения.

Работу стоит оценивать как воспроизводимый и проверяемый алгоритмический эксперимент с обоснованным механизмом, а не как доказанное универсальное превосходство. Практический выбор должен опираться на частоту несущественных изменений и цену действительного обхода.

## 7. Воспроизведение

```bash
pip install -r requirements-md-astar.txt
python -m mesha.selfcheck
python -m mesha.selfcheck_deferred
python -m mesha.validate_md_suite
python -m mesha.md_benchmark --run --cohort all
python tools_md_analyze.py
python tools_md_report.py --pdf
python tools_md_notebook.py --execute
```

Сохранённые CSV/JSON не являются новым измерением: runner возобновляет имеющийся `raw.jsonl`. Для нового прогона в одной среде нужно предварительно переименовать raw-файл, environment и completion. Ветку, все исходники, зафиксированный JSON задач, сырые повторы, коэффициенты и SHA-256 можно перенести обычным git clone или прилагаемым git bundle. Нужны NumPy/Matplotlib; для PDF — Pandoc/XeLaTeX.

Первоисточники: Agranovskiy & Yakovlev, MeshA\*, AAAI 2026, DOI 10.1609/aaai.v40i43.41004; Hernández, Asín & Baier, MPGAA\*, AAAI 2015, DOI 10.1609/aaai.v29i1.9355; Koenig & Likhachev, D\* Lite, AAAI 2002. Более подробное сопоставление с DPA\*, GAA\*, L-GLS и геометрическими областями улучшения содержится в [описании метода](method.md).
