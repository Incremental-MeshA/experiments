# C-Mesh-D* Lite, Suffix-Mesh и Boundary-Mesh: C++

Три ранее предложенных варианта перенесены в ветку `research/md-astar` и используют **те же float-стоимости, ID и collision traces**, что и прежние 11 алгоритмов в `cpp/experiments`. Определения старых прототипов сохранены в [reference](reference/origin.json); их целочисленные результаты в эту серию не входят.

В сохранённой новой серии C-Mesh завершил **85/90** car16 replay-эпизодов, Suffix-Mesh — **79/90**, Boundary-Mesh — **90/90** при лимите миллиона раскрытий на запрос; положительный префиксный контроль — 79/90. На основной mixed-серии C-Mesh и Boundary ускорили ремонт относительно D* Lite lattice в **4,81×** и **8,00×** (12/12 пар). MD-A* и LBA* reuse обычно быстрее новых вариантов; универсального преимущества нет. По сумме медианных времён на двух корнях Berlin/mixed выиграл Boundary-Mesh: 0,216 с против 0,453 с у самого быстрого прежнего точного контроля D* Lite lattice.

Реализация находится в [variants.hpp](variants.hpp). Все четыре новых адаптера используют одно ядро D* Lite, одинаковую очередь и политику уведомлений. Цель фиксирована, старт может перемещаться; поддерживаются блокировки и освобождения клеток.

| ID запуска | Что изменено |
| --- | --- |
| `prefix_positive` | Контроль: исходный префиксный mesh с положительными весами |
| `cmesh_dstar` | **C-Mesh-D* Lite**: сжатие цепочек, чьи внутренние конфигурации имеют одну входящую и одну исходящую дугу; начальные конфигурации сохраняются |
| `suffix_mesh` | **Suffix-Mesh D* Lite**: развернуть физические примитивы, построить префиксный mesh, развернуть дуги обратно; поиск от цели разделяет общие суффиксы исходных примитивов |
| `boundary_mesh` | **Boundary-Mesh D* Lite**: метки D* Lite только на состояниях решётки, полные веса примитивов, одна кешированная маска допустимости на `(клетка, heading)`, вычисляемая обходом префиксного mesh |

Suffix-Mesh — топология графа, а не сохранённый суффикс пути `lba_reuse`. Слово `boundary` в старом `cpp/experiments/dstar_boundary.hpp` обозначает численную границу остановки и не является реализацией Boundary-Mesh.

## Сохранение задачи

Для префиксного mesh потенциал регулярной конфигурации равен `rho=delta*depth`, а на границе примитива — нулю. Вес дуги равен `c0+rho(v)-rho(u)`. `delta` — степень двойки, не превышающая `min primitive cost / (4*(max depth+1))`. Все дуги положительны; сумма вдоль полного примитива сохраняет его исходную стоимость. Округление стоимостей в микростоимости старого прототипа здесь отсутствует. Для суффиксного графа положительные веса наследуются при развороте, потенциал меняет знак.

У сжатой дуги сохраняются **все** клетки внутреннего trace, включая начало и конец. Уведомление учитывает каждую из этих клеток. В Boundary-Mesh изменение клетки инвалидирует всю затронутую маску. Уведомления работают и для ранее запрещённых дуг; геометрические предшественники регистрируются независимо от текущей проходимости, чтобы открытие нового компонента не терялось.

`notify_probes` новых адаптеров считает просмотр групп зависимости от клеток. Этот счётчик уже, чем все накладные расходы обновления: ноль у другого метода не означает отсутствие работы. Столбцы CSV описаны в [прежнем словаре](../experiments/README.md).

## Запуск

Для нативных запусков нужны C++17 и Python 3; входы уже сохранены. Тесты и анализ используют NumPy, графики — Matplotlib, сборка PDF — Pandoc, XeLaTeX и шрифты Noto, проверка PDF — PyMuPDF. Исходная Python-модель примитивов из этого репозитория нужна только тестам и подготовке новых входов.

Общий [ноутбук](../../docs/experiments/analysis.ipynb) содержит обе серии. Его повторное исполнение: `python cpp/mesh_variants/notebook.py`; нужны nbformat, nbclient и ipykernel. Скрипт сохраняет обе части ноутбука.

```bash
make -C cpp/mesh_variants -j2 all
make -C cpp/mesh_variants sanitize
python cpp/mesh_variants/test_variants.py

# Входы уже зафиксированы: повторно генерировать их не нужно.
python cpp/mesh_variants/run_all.py --output cpp/mesh_variants/results/reproduction
python cpp/mesh_variants/analyze.py --directory cpp/mesh_variants/results/reproduction
python cpp/mesh_variants/report.py --directory cpp/mesh_variants/results/reproduction
python cpp/experiments/report.py --mesh-directory cpp/mesh_variants/results/reproduction
```

Для одного метода:

```bash
cpp/mesh_variants/build/experiment \
  --input cpp/experiments/frozen/car16_replay.txt \
  --output /tmp/cmesh.csv --methods cmesh_dstar --repeats 3
```

`--mode models` без `--output` проверяет проекцию каждого физического примитива, согласованность эвристики и выводит размеры графов. `build/experiment_memory` отдельно измеряет requested C++ heap.

## Общая серия и проверки

Новая серия содержит прежние 11 методов, три запрошенных метода и `prefix_positive`: **15 методов на тех же 186 replay-эпизодах и 40 параметризованных миссиях**, три временных повтора и отдельный replay-проход памяти. Это новый совместный запуск; времена двух серий не смешиваются. Лимиты совпадают: миллион раскрытий на запрос; 160/256 шагов собственной car16/grid8-навигации. Неудачи и запросы после исчерпания бюджета сохраняются.

Подготовка четырёх общих шаблонов выполняется один раз вне таймеров планировщиков. Её время и общий requested heap явно выводятся в `*.csv.json`; они не скрыты в покомандной памяти. Общая модель содержит сразу четыре шаблона и контрольную информацию для проверки проекций, поэтому её размер не является размером минимально необходимого единственного шаблона в рабочем приложении.

Тесты используют независимый Python Dijkstra непосредственно на физических примитивах, все 16 направлений, перемещение старта, закрытие/открытие внутренних клеток макродуг, открытие недостижимого компонента, блокировку/освобождение концов, ASan/UBSan, совпадение путей и счётчиков обычного и allocation-бинарника. Проверка целого бенчмарка дополнительно сверяет каждую завершённую точную стоимость с эталоном на той же карте знаний и каждое исполненное движение с истинной картой.

В `grid8` все примитивы имеют один переход: префиксный mesh, C-Mesh и Suffix-Mesh вырождаются в один граф. Эта серия контролирует накладные расходы и инкрементальный ремонт, но не доказывает пользу разделения префиксов/суффиксов.

Результаты и проверяемые хеши находятся в `results/full`. Основной [отчёт](../../docs/experiments/report.md) дополняется отдельной главой новой серии; подробное [дополнение](../../docs/experiments/mesh_variants.md) содержит все 15 методов.

Проверка сохранённого артефакта: `python cpp/mesh_variants/validate_artifact.py`. Флаг `--smoke` дополнительно собирает обычный и allocation-бинарники и запускает небольшой общий replay на обеих моделях. Эта проверка не перезаписывает измерения; временные выходы создаются в `/tmp`.
