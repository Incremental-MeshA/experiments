# Incremental Mesh A\*

Исследовательский артефакт: реализация, доказательства, динамические бенчмарки и статья на русском языке.

## Ветка исследования преимущества ремонта

`research/repair-advantage` сохраняет исходное исследование и добавляет отдельную
реализацию [src/repair.cpp](src/repair.cpp). Основные варианты: MIR/MIR-F
(фильтр влияния mesh и сохранение равноценного родителя), MFR (дерево от
старта), MDF (дерево от цели), MSP (выборочный ремонт эвристики через mesh) и CSB
(сертификат по покрытым клеткам и суффиксные мосты). Общие идеи ремонта деревьев,
GAA* и повторного использования путей имеют предшественников; область вклада и
доказательства указаны в [описании методов](paper/repair_methods_ru.md).

```bash
make repair bin/repair_v1 bin/ima
make test-repair
bin/repair --model data/base_lattice.model \
  --workload workloads/Berlin_2_256__base__fixed__local__0.work \
  --algorithm mfr --dump
python benchmark_repair.py --stage prepare
python benchmark_repair.py --repeats 3
python analyze_repair.py --plots
python benchmark_influence.py --stage prepare
python benchmark_influence.py --stage run
python benchmark_influence.py --stage analyze
python mechanism_repair.py --stage prepare
python mechanism_repair.py --stage run
python mechanism_repair.py --stage analyze
python render_repair.py --pdf
```

Порядок важен: подготовка, тесты и сборки завершаются **до** измерений. Процессы
поиска измеряются последовательно. Старые CSV используются только для проверки
стоимости; все временны́е сравнения новой фазы измеряются заново. `--audit`
проверяет внутренние инварианты и применяется в тестах, а не в измерениях.
`--dump` печатает ID примитивов в stderr. Встроенная проверка извлечённой
траектории выполняется и в обычном режиме за пределами таймера.

Бенчмарки возобновляют завершённые серии по сохранённым CSV. Чтобы действительно
измерить опубликованный набор заново, сохраните соответствующий каталог `raw`
под другим именем перед запуском. Первый бенчмарк также принимает `--label`
(например, `--label repeat_raw` вместе с `analyze_repair.py --label repeat_raw`).
Контрольные суммы защищают от смешивания результатов разных бинарников.

Проверка готового архива и PDF: `python validate_repair.py` (дополнительные
зависимости — `requirements-validation.txt`). Она пересобирает обе версии в
временной папке, сверяет бинарники, стоимости, переносимость путей и границы
всех четырёх векторных рисунков с учётом преобразований PDF.

Свежие контроли `fresh`, `fresh-mesh`, `fresh-backward` используют то же ядро.
Остальные доступные варианты: `gaa`, `gaa-plain`, `msp`, `bridge-eager`, `csb`,
`forest`, `mdf`, `mfr`, `mir`, `mir-forward`, `mir-filter`, `mdf-rp`.
MFR и MIR-F очищают дерево при смене старта; MDF/MIR сохраняют корень
у цели. Ни один вариант не предполагает, что освобождение клеток невозможно.

Основные результаты новой фазы находятся в `results/repair/`, полные измерения —
в `results/repair/raw/`, механизмный тест локальности — отдельно в
`results/repair/mechanism/`. Доработка MIR измерена заново вместе с контролями в
`results/repair/influence/`; после просмотра первых 60 задач ей выделены новые
12 задач с seed 1005. Первая версия зафиксирована в `frozen/v1/repair.cpp`,
её бинарник `bin/repair_v1` используется первым и механизмным бенчмарками.
Пилоты сохранены отдельно и в итоговую статистику не
входят. Готовый дополнительный отчёт: [PDF](paper/repair_advantage_ru.pdf),
[Markdown](paper/repair_advantage_ru.md). Исходная статья ниже относится к
замороженной базовой реализации.

Измеренный положительный пример: на Berlin/base/fixed/local/seed0 MIR-F ускоряет
настоящий ремонт в **3,53 раза** относительно лучшего из трёх свежих A*.
На контролируемом тесте локальности из 12 серий медианное ускорение настоящего
ремонта — **2,74× для MDF** и **2,67× для MFR**.
На основном наборе из 48 серий его медианы — **0,48×** по всем перепланированиям
и **0,37×** по настоящему ремонту: общего преимущества нет. Эти ограничения,
результаты нового seed и механизмный тест приведены в
[кратком отчёте](results/repair/REPORT_RU.md). Счётчики выполненной работы и
скорость оцениваются отдельно.

Готовые материалы: [статья PDF](paper/article_ru.pdf), [исходник Markdown](paper/article_ru.md), [LaTeX](paper/article_ru.tex), [краткий отчёт](results/REPORT_RU.md).

Mesh здесь — граф расширенных клеток из **Agranovskiy & Yakovlev, MeshA\*: Efficient Path Planning with Motion Primitives, AAAI 2026**, а не навигационная триангуляция. Исходная статья: <https://doi.org/10.1609/aaai.v40i43.41004>.

## Что реализовано

| Метод | Поисковые метки | Проверка допустимости |
| --- | --- | --- |
| Lattice A\*, LPA\*, D\* Lite | Состояния `(r,c,heading)` | Полный trace каждого примитива |
| Mesh A\*, Mesh-LPA\*, Mesh-D\* Lite | Начальные и регулярные расширенные клетки | Следующая клетка префикса |
| C-Mesh A\*, C-Mesh-LPA\*, C-Mesh-D\* Lite | Mesh после сжатия цепочек с indegree=outdegree=1 | Все клетки макроребра |
| Cached Lattice LPA\*/D\* Lite | Состояния решётки + точечный кеш рёбер | Перепроверка только инвалидированных примитивов |
| Boundary-Mesh LPA\*/D\* Lite | Состояния решётки + кеш масок наборов | Пакетный обход mesh с общими префиксами |
| Suffix-Mesh D\* Lite | Начальные и регулярные клетки суффиксного mesh | Объединение в направлении поиска от цели |

LPA\* применим к фиксированному старту. D\* Lite допускает перемещение старта между позами решётки при фиксированной цели. Поддерживаются добавление **и удаление** препятствий. Изменение набора примитивов требует перестроения моделей.

В mesh используются положительные стоимости `cρ(u,v)=c0(u,v)+δ*depth(v)-δ*depth(u)`. На границе примитивов потенциал равен нулю, поэтому целевая функция точно сохраняется. Стоимости примитивов один раз округлены до микростоимостей; оптимальность относится к этой целочисленной задаче.

## Быстрый запуск

Нужны Python 3.10+ и компилятор C++17. Поиск и тесты не требуют Python-пакетов или сети.

```bash
cd incremental_mesh_astar
make
python prepare.py
python prepare_suffix.py
python tests/verify.py
python tests/verify_suffix.py
bin/ima --model data/base_lattice.model \
  --workload workloads/Berlin_2_256__base__fixed__local__0.work \
  --algorithm dlite-batch --dump
```

`--dump` пишет последовательности ID примитивов в stderr; CSV с измерениями — в stdout. Коды завершения ненулевые при нарушении восстановления, несовпадении стоимостей или ошибке входа. Отсутствие пути обозначается стоимостью `-1` в CSV.

Алгоритмы CLI:

- `astar`, `dijkstra`, `lpa`, `dlite` — работают с соответствующей моделью `lattice`, `mesh` или `cmesh`.
- `dlite-cached`, `lpa-cached` — решётка с точечным кешем допустимости.
- `dlite-batch`, `lpa-batch` — Boundary-Mesh, запускаются с **lattice-моделью**, соседняя `mesh`-модель подключается автоматически.
- `astar-cached`, `astar-batch` — дополнительные контрольные варианты, используемые в тестах.
- `dlite-scan` — абляция уведомлений полным сканированием; на больших графах дорогая.

Suffix-вариант запускается отдельной сборкой:

```bash
bin/ima_suffix --model data/base_suffix.model \
  --workload workloads/Berlin_2_256__base__fixed__local__0.work \
  --algorithm dlite
```

## Воспроизведение основного эксперимента

Для анализа нужны `numpy`, `pandas`, `matplotlib` из `requirements.txt`.

Для сборки PDF также нужны Pandoc, XeLaTeX с пакетами `float` и `fvextra` и шрифты Noto Serif, Noto Sans, DejaVu Sans Mono. Пути к иллюстрациям в Markdown/LaTeX заданы от корня проекта; LaTeX можно собрать из корня командой `xelatex -output-directory=paper paper/article_ru.tex`. Для принудительной пересборки бинарников из исходников используйте `make -B`. В выполненном эксперименте обе такие сборки побайтово совпали с измеренными бинарниками; контрольные суммы — `results/build_reproducibility.json`.

```bash
python benchmark.py --design balanced --seeds 4 --repeats 3 \
  --episodes 16 --label balanced
python suffix_benchmark.py
python analyze.py --label balanced
python analyze_suffix.py
python plots_extra.py
python render_paper.py --pdf
```

Измеряемые процессы запускаются последовательно, порядок методов рандомизирован. Для 24 фиксированных задач выполняются 13 вариантов, для 24 движущихся — 8. Три повторения дают **1512 запусков** и **25704 измеренных запросов**, соответствующих **816 различным снимкам**. Статистика считает независимыми задачи, а не повторения или последовательные эпизоды. Время включает применение изменений, уведомления/инвалидирование, поиск и восстановление пути. Валидация результата и ввод-вывод исключены из таймера. Пиковый RSS включает процесс целиком.

Отдельная фаза направления добавляет **432 запуска**: Suffix-Mesh и заново измеренные Prefix-Mesh и Cached Lattice D\* Lite на тех же задачах, по три повторения со случайным порядком. Итого в двух фазах **1944 запуска / 33048 измеренных запросов**. Результаты этой фазы сохраняются в `results/suffix/`, анализ — `suffix_analysis.json`; её коэффициенты считаются относительно её собственных бейзлайнов.

Подмножество выбирается детерминированно по формуле `(seed + 2*map_index + 3*control_index) % 6`. Порядок карт: `random`, `rooms`, `warehouse`, `Berlin_2_256`, `AR0307SR`, `ht_0_hightown`; порядок наборов: `base`, `add`. Чётность слота задаёт fixed/moving, целая часть деления слота на два задаёт local/path/churn. Это сбалансированный неполный факторный план из 48 задач в 24 seed-блоках, не весь факторный набор. Стратифицированный bootstrap перевыбирает seeds внутри каждой карты и удерживает оба набора примитивов в одном блоке.

Подготовлены все 288 workloads полного плана. Для расширенного прогона:

```bash
python benchmark.py --design factorial --seeds 4 --repeats 3 \
  --episodes 16 --label full_factorial
python analyze.py --label full_factorial
```

Полный прогон требует существенно больше времени и памяти. Скрипт сохраняет только завершённые успешные CSV, позволяет продолжить запуск и пишет ошибки/таймауты в `failures.json`. Наличие полного набора входов не означает, что все его результаты включены в статью. Экспериментальные результаты статьи берутся только из `results/balanced/`; пилотные файлы других каталогов в анализ не входят.

Чтобы повторить измерения заново, задайте новую `--label`. Повторный запуск с существующей меткой пропускает сохранённые результаты. При изменении бинарника или параметров используйте новую метку; не смешивайте разные версии в одной таблице.

## Структура

- `prepare.py`: разбор авторских примитивов, построение автомата mesh, проверка инварианта начала, положительное перевзвешивание и сжатие C-Mesh.
- `src/ima.cpp`: направленные графы, одно ядро A\*/LPA\*/D\* Lite, обратные индексы, кеши и генератор последовательностей.
- `tests/verify.py`: независимый Python Dijkstra и проверка экспортированных примитивов; специальные случаи с восстановлением пути после открытия прохода.
- `prepare_suffix.py`, `tests/verify_suffix.py`: суффиксный граф, его эвристика, независимые проверки всех ориентаций.
- `benchmark.py`: генерация карт, сбалансированный/полный план, последовательные повторные измерения, проверка равенства стоимостей.
- `analyze.py`: парные отношения времени на последовательностях, кластерный bootstrap, таблицы, PNG/PDF графики.
- `render_paper.py`: подстановка **измеренных** значений в статью и сборка PDF через Pandoc/XeLaTeX.
- `data/`: готовые модели и описания примитивов, исходные control sets, их лицензия и SHA-256.
- `maps/`: три синтетические и три полные карты MovingAI.
- `workloads/`: заранее сохранённые изменения и старты, одинаковые для всех методов.
- `results/verification.json`: фактический отчёт о проверках.
- `results/balanced/`: сырые CSV каждого метода и повторения, пиковый RSS, среда и хеш бинарника.
- `results/sequence_metrics.csv`, `summary.csv`, `analysis.json`, `comparisons.json`: агрегаты и описание выполненной оценки.
- `paper/article_ru.md`, `paper/article_ru.pdf`: итоговая статья.

## Формат workload

Первая строка — путь к карте. Вторая: `start_r start_c start_heading goal_r goal_c goal_heading`. Затем для каждого эпизода: `current_r current_c current_heading change_count` и `change_count` строк `r c blocked`, где `blocked` равно 0 или 1. Координаты нумеруются с нуля. Для перенесённых файлов загрузчик ищет недоступную карту по её имени в локальном каталоге `maps/` рядом с `workloads/`.

## Формат моделей и гарантия реконструкции

Текстовые `.model` содержат примитивы, конфигурации, рёбра, support и параметры `δ/α`. Конфигурации первых 16 ID соответствуют начальным направлениям. Регулярные состояния несут единственное начало примитива. У каждого ребра, завершающего примитив, сохранён его ID. После каждого запроса C++ независимо от поисковых меток проверяет начальное направление каждого примитива, все swept cells, конечную позу и сумму стоимостей.

Индекс включает также запрещённые рёбра. Соседи материализуются геометрически даже при цене `∞`, чтобы последующее удаление препятствия могло улучшить путь. Для C-Mesh support включает внутренние клетки цепочек. В Boundary-Mesh изменение в объединённом support инвалидирует всю маску, а в Cached Lattice — отдельное ребро.
