# Разнообразные инкрементальные эксперименты C++

11 методов, одинаковые запросы и отдельная навигация по неизвестной карте. Результаты новой серии находятся в `results/expanded/`; времена из прежних Python/C++-серий сюда не подмешиваются. Подробная постановка: [протокол](../../docs/experiments/protocol.md). Итоги: [отчёт](../../docs/experiments/report.md), [PDF](../../docs/experiments/report.pdf), [графики](../../docs/experiments/figures).

Дополнительные реализации **C-Mesh-D\* Lite, Suffix-Mesh, Boundary-Mesh** и контроль положительного prefix вынесены в [cpp/mesh_variants](../mesh_variants/README.md). Их совместный запуск с этими 11 методами хранится отдельно в `../mesh_variants/results/full`: это новая серия из 15 методов на тех же входах. Основной отчёт содержит обе серии с явным разграничением времён.

## Быстрый просмотр и воспроизведение

Из корня репозитория, Python 3.12+, GCC с C++17, NumPy и Matplotlib из корневого `requirements.txt`:

```bash
make -C cpp/experiments -j2
python cpp/experiments/test_protocols.py
python cpp/experiments/test_grid8.py
python cpp/experiments/analyze.py
python cpp/experiments/report.py
```

Первые две команды собирают C++ и проверяют протокол. Последние две проверяют хеши сохранённых данных, заново строят таблицы, графики и отчёт. Для PDF нужны Pandoc, XeLaTeX и шрифты Noto Serif / Noto Sans Mono. Сборка и исполнение C++ не зависят от Python во время измеряемого поиска.

Новый полный замер на **сохранённых** входах:

```bash
python cpp/experiments/run_all.py --output cpp/experiments/results/reproduction
python cpp/experiments/analyze.py --directory cpp/experiments/results/reproduction
python cpp/experiments/report.py --directory cpp/experiments/results/reproduction
```

`run_all.py` запускает задания последовательно: три повтора времени для каждого метода и затем один отдельный проход памяти для replay. Сборка происходит до замеров. Каталог результатов должен быть новым; возобновляются только полностью завершённые задания с совпадающими хешами. Прерванный незавершённый проход сохраняется, для нового запуска следует выбрать другой каталог. Не запускайте одновременно другие тесты, сборки и анализ на машине измерения. Графики и отчёт по умолчанию обновляются в `docs/experiments`; сохраните их перед анализом новой серии.

Быстрый выбор одного сценария и методов:

```bash
cpp/experiments/build/experiment --input cpp/experiments/frozen/car16_replay.txt --output /tmp/ima-example.csv --case history --methods mpgaa,md_astar,lba_reuse --repeats 3 --cap 1000000
```

Выходной CSV и его JSON не перезаписываются. `--mode mission --radius 8 --max-steps 160` включает собственную навигацию; для неё передавайте `car16_missions_r8.txt`, а не replay. Радиус должен покрывать весь следующий примитив. Все 11 методов запускаются по умолчанию.

Проверка ASAN/UBSan:

```bash
make -C cpp/experiments sanitize
python cpp/experiments/test_protocols.py
```

Генерация из исходных карт выполняется отдельно, до времени кандидатов:

```bash
python cpp/experiments/prepare.py
```

Генератор отказывается работать, если `frozen/manifest.json` уже существует. Для новой версии входов используйте отдельную копию репозитория и сохраните прежний `frozen/` под другим именем; команда создаст новый набор. Для воспроизведения опубликованных замеров генерация не нужна. Не меняйте входы или исходники измеряемого бинарника посреди серии. Официальные карты уже включены вместе с [происхождением и атрибуцией](maps/README.md). Корни, отказы выбора и все события сохранены; сеть при замерах не используется.

После анализа можно заново выполнить [ноутбук](../../docs/experiments/analysis.ipynb): `python cpp/experiments/notebook.py` (нужны nbformat/nbclient из корневого requirements). Контрпример старого D\* Lite отдельно воспроизводится командой `python cpp/experiments/reproduce_legacy_failure.py`; она собирает архивный код и проверяет именно ожидаемый отказ. Такие проверки выполняйте вне временных замеров.

## Наборы и методы

- `car16_replay`: 90 эпизодов, 835 запросов. Длинные примитивы машины, шесть основных карт, вставки на/вне контрольного пути, смешанные освобождения/блокировки, локальное раскрытие, размеры пакетов, периоды изменений, радиусы, отдельная диагностика истории.
- `grid8_replay`: 96 эпизодов, 2122 запроса. Дополнительная сеточная модель на четырёх фиксированных картах 50×50; протокол динамики и локальных наблюдений адаптирован из MPGAA\* 2015. Это не полное воспроизведение работы и не замена car16.
- `*_missions_r*`: 40 параметризованных миссий с полностью неизвестной начальной картой. Каждый метод движется по собственному пути; сенсор раскрывает квадрат вокруг текущего положения.

У разных параметров повторяются одни и те же карта/корень. Они не являются независимыми случайными задачами. «На пути» в replay означает путь контрольного LBA\*, который может отличаться от другого равностоимостного пути.

Методы: `lba`, `lazy_lba`, `mesha`, `mesh_parall`, `dstar_lattice`, `dstar_mesh`, `mpgaa`, `md_astar`, `md64`, `md_scan`; их ядра не меняются относительно предыдущей C++-серии. Новый `lba_reuse` — стандартный контроль сохранения допустимого оптимального суффикса при одних увеличениях стоимости. Он нужен, чтобы не приписывать MD-A\* выигрыш, доступный обычному A\* с кешированием пути. `mesh_parall` приближённый; остальные проверяются по оптимальной стоимости.

Исключение в запускателе: обе версии D\* Lite используют экспериментальный `dstar_boundary.hpp`, исправляющий преждевременную остановку при float-ключах на нулевых mesh-префиксах. Графовый адаптер и старый заголовок сохранены. Причина, первый остановленный проход и старые исходники находятся в [pre_boundary_fix](results/pre_boundary_fix/README.md). Его времена не смешиваются с основной повторной серией.

## Словарь CSV

Идентификатор строки — `case, method, repeat, query`. В replay `query` обозначает общий запрос; в mission это шаг симулятора, на котором планировщик мог не вызываться (`planned=0`).

| Поля | Смысл |
| --- | --- |
| `status` | `ok`, `no_path` (доказан по карте знаний), `follow`, `goal`, `capped`, `skipped_after_cap`, `step_limit` |
| `time_s`, `setup_s` | Поиск/ремонт вместе с правками, извлечением и кешированием пути; отдельно конструктор на первом запросе |
| `cost`, `expected` | Стоимость ответа и независимого точного контроля на **той же карте знаний**; пустое значение означает бесконечность либо отсутствие вызова |
| `blocks`, `opens` | Полученные изменения карты знаний, а не число неизвестных глобальных изменений мира |
| `revealed`, `known` | Новые и накопленные наблюдаемые клетки в mission, включая свободные |
| `travel_cost`, `sensing_s` | Накопленный фактический путь и отдельно работа сенсора; вне времени планировщика |
| `expansions` | Раскрытия A\*/MPGAA или извлечения согласуемых вершин D\* Lite; разные представления не имеют одинаковой цены раскрытия |
| `checked_cells` | Фактические обращения к клеткам при проверках коллизий внутри ядра, без внешнего валидатора |
| `notify_probes`, `heuristic_pops` | Только инструментированные уведомления и очередь снижения эвристики MPGAA/MD; ноль у другого метода не означает отсутствие всей работы обновления |
| `certified`, `backend_calls` | Ответ сохранённым оптимальным путём без вызова поискового ядра; число вызовов ядра MD/MPGAA или явного контроля |
| `activated_cells`, `deferred_cells`, `refined_cells` | Освобождения, активированные сейчас; отложенные клетки после запроса; проверки нижней оценки MD |
| `peak_heap_bytes`, `retained_heap_bytes` | Пик внутри запроса и живые запрошенные heap-байты алгоритма с результатом; только отдельный replay-проход памяти |
| `path_hash` | Стабильный хеш последовательности примитивов для проверки повторов и инструментирования |
| `start_*`, `next_*` | Текущее и фактически исполненное следующее состояние; при отсутствии движения совпадают |

Память здесь не RSS: исключены общая модель, стек, malloc-метаданные и внешняя проверка. Таймер не включает сенсор, контрольный поиск и проверку истинного мира. Полный эпизод = сумма `time_s + setup_s`; онлайн-ремонт исключает первичный запрос. Лимит миллион раскрытий — общий для двух вызовов MD. После превышения бюджета replay сохраняет оставшиеся запросы как `skipped_after_cap`. Быстрый отказ не считается успешным решением, а недостижимость в replay является корректным вычисленным ответом.

Графики задержек условны на запросах, закончившихся в бюджете; рядом приводятся доли завершения и профили со штрафом бесконечности. Бутстреп в отчёте описательный, по картам, а не по тысячам зависимых запросов. Числа исходного Python-эксперимента не используются для расчёта ускорений.
