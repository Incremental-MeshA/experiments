# Stamp, Batch и Witness для incremental mesh MPGAA*

Ветка `research/mpgaa-mesh-lazy` продолжает `research/mpgaa-mesh-four` (`3b63d6b`). Прежние исходники, данные и отчеты не изменены. Новые реализации C++17 находятся в [algorithms.hpp](algorithms.hpp), точка выбора методов — [factory.hpp](factory.hpp).

| Алгоритм | CLI | Механизм |
| --- | --- | --- |
| Stamp-Mesh-MPGAA* | `stamp_mpgaa` | Версии плиток 8×8, ленивое обновление масок коллизий и проверка сохраненного продолжения |
| Batch-Mesh-MPGAA* | `batch_mpgaa` | Stamp + выбор между обратной проекцией освобождений и просмотром исходящих дуг обученных состояний |
| Witness-Mesh-MPGAA* | `witness_mpgaa` | Batch + объединение препятствий в сертификат покрытия ветви, включая ее свободный префикс |
| Абляция Stamp | `stamp_cell` | Версия каждой клетки вместо плитки; остальные правила те же |
| Абляция Batch | `batch_scan` | При каждом релевантном освобождении принудительный просмотр всех обученных состояний |

Это исследовательские сочетания известных приемов, без заявления литературного приоритета. Цель фиксирована; поддержаны направленные примитивы car16 и grid8, блокировки и освобождения. Поиск остается на исходном графе примитивов. Mesh использует исходные упорядоченные трассы и их общие префиксы; стоимость, геометрия и идентификаторы дуг не меняются.

На 90 car16 replay-конфигурациях Stamp дает 1.29× по полному времени и 2.09× по online относительно Boundary, Batch — 1.31× и 2.12×, Witness — 1.28× и 2.06×. Новые варианты расходуют примерно на 4–5% больше пикового heap относительно Boundary в геометрическом среднем. Самый быстрый завершившийся прежний метод выбирается отдельно для каждой конфигурации; все новые методы проигрывают этой огибающей в среднем. Batch выигрывает от 10% в 14/90 car16 replay-конфигурациях, главным образом при смешанных правках. На grid8 сильный Octile A* reuse существенно быстрее. Дополнительный выигрыш Batch над Stamp по полному эпизоду невелик; Witness в текущей дешевой проверке занятости не окупился.

При блокировках допустимость эвристики сохраняется. Изменения только записывают версии плиток; устаревшие маски обновляются по требованию. Каждый переход сохраненной MPGAA-цепочки проверяется перед принятием ответа. При освобождениях оба способа Batch полностью ремонтируют эвристику до поиска: начальные нарушения дополняются распространением по предшественникам. Остающиеся занятыми Witness-узлы объединяют покрытые примитивы: если они покрывают всех членов ветви, она пропускается до чтения ее свободного префикса. Состояния за ним не нуждаются в обратных подписках.

## Сборка и проверка

```bash
make -C cpp/mpgaa_lazy -j2 all
make -C cpp/mpgaa_lazy test
make -C cpp/mpgaa_lazy sanitize
cpp/mpgaa_lazy/build/test_sanitize cpp/experiments/frozen/grid8_model.txt
cpp/mpgaa_lazy/build/test_sanitize cpp/experiments/frozen/car16_model.txt
```

Независимый Дейкстра перечисляет исходные примитивы и напрямую читает занятость, не использует mesh, кеш или обученную эвристику. Тесты включают 1 296 случайных динамических снимков, синтетический тест покрытия и всего 7 790 сравнений. Проверены смешанные и односторонние пакеты, блокировки конечных состояний, повторы уведомлений, пустые пакеты, разные размеры плиток, нулевой бюджет и восстановление после него. Аудит не изменяет планировщик. Устаревшие маски разрешены до их чтения. Синтетический тест требует сокращения чтений Witness с 10 до 2 на длинном общем префиксе с двумя глубокими препятствиями.

## Измерения

Ранняя незавершенная серия с Witness без совместного покрытия сохранена в `results/pre_witness_cover` и исключена. После проверки механизма весь набор повторен заново, включая контроли; матрица карт, параметров и методов сохранена.

Дополнительный `regression.py` использует Дейкстру на Python для целевых проверок: блокировка и открытие цели, два препятствия одной трассы, освобождение клетки за остающимся препятствием, повторное открытие, блокировка старта и `start == goal`. Эти нетаймированные проверки выполняются после измерений, не входят в 298 конфигураций и не используются для подбора параметров.

Зафиксированный до временных измерений [манифест](frozen/manifest.json) содержит входные хеши, исходники, методы и задания. `prepare.py` отказывается перезаписывать существующий манифест. Новый запуск:

```bash
python cpp/mpgaa_lazy/run_all.py --output cpp/mpgaa_lazy/results/reproduction
python cpp/mpgaa_lazy/analyze.py --directory cpp/mpgaa_lazy/results/reproduction
python cpp/mpgaa_lazy/report.py --directory cpp/mpgaa_lazy/results/reproduction
```

Официальный набор содержит 298 конфигураций: все 186 прежних replay, 64 динамические миссии (16 карт × два корня × две опорные точки `(k,cr)=(2,5),(32,20)`, `n=k`) и 48 миссий раскрытия неизвестной карты (шесть car16-карт × два корня × радиусы 8/16/32/64). Это подмножество динамической сетки, а не повтор всех 36 сочетаний k/cr. Число случайных блокировок и освобождений ограничено размерами исходных пулов; фактический cr сохранен в отчетных таблицах.

Три последовательных повтора времени с перемешиванием методов; отдельный одинарный проход запрошенных heap-байтов на каждой конфигурации. Перед официальными измерениями оба harness и профилировщик проверены на 24 180 совпадающих строках. Времена всех контролей собраны заново. Незавершенный запуск не перезаписывается: для новой попытки нужен новый каталог.

Контроли: исходный MPGAA*, LBA* reuse, MD-A*, четыре предыдущих mesh-MPGAA; на grid8 также Octile A* reuse. Остальные прежние алгоритмы здесь заново не измеряются. `best_control` в анализе выбирает самый быстрый завершившийся контроль по полному эпизоду после замера. В динамической навигации траектории и наблюдения могут различаться между алгоритмами; replay дает одинаковые запросы.

`episode_s` включает конструктор планировщика и все его вызовы; `online_s` исключает первый вызов и конструктор. Часы включают нормализацию правок, изменение карты, уведомления, ремонт эвристики, поиск, обучение и сборку ответа. Генератор среды, сенсор, точный контрольный поиск и компиляция общей модели исключены. Память — максимум запрошенных C++ heap-байтов планировщика и его ответа; это не RSS. В обычной сборке heap-поля нулевые и не являются замером: используйте `memory_metrics.csv` или объединенный `case_metrics.csv`. Версии плиток и копия карты планировщика включены, общая модель исключена.

Новые счетчики: `stamp_writes`, `tile_reads`, `mask_refreshes`, `mask_hits`, `cut_checks`, `cut_reuses`, `cut_primitives`, `edit_batches`, `scan_batches`, `seed_tests`, `arrow_checks`, `cover_tests`. `checked_cells` считает проверки занятости при обработке дуг, включая старое сечение; служебные проверки старта и цели в него не входят. `notify_probes` у edit-join считает группы смещений, у scan — дуги обученных состояний; это разные единицы работы, их нельзя трактовать как равную цену.

Ход длинного запуска можно читать командой `python cpp/mpgaa_lazy/progress.py` без загрузки больших CSV.

Отчет, графики и выполненный notebook находятся в [docs/mpgaa_lazy](../../docs/mpgaa_lazy). Анализ использует неизмененные функции проверки и агрегации из `cpp/mpgaa_mesh/analyze.py`; их хеш зафиксирован в новом артефакте. `validate_artifact.py` пересобирает измеренные бинарники, проверяет независимые тесты и воспроизводимость всех таблиц и графиков.
