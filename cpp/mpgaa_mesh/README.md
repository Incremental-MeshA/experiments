# Четыре сочетания mesh и MPGAA*

Реализации C++17 находятся в `algorithms.hpp`; исходные планировщики в `cpp/include/ima` и прежние результаты сохранены без изменений. Эта работа сделана в отдельной копии репозитория и ветке `research/mpgaa-mesh-four` от `691b8f0`.

| Метод | Имя в CLI | Изменение относительно общего MPGAA* |
| --- | --- | --- |
| Boundary-MPGAA* | `boundary_mpgaa` | Совместная проверка исходных трасс по дереву общих префиксов |
| Selective-Mesh-MPGAA* | `selective_mpgaa` | Допустимый сохранённый путь задаёт верхнюю границу; обученная эвристика отсекает целые ветви |
| Delta-Mesh-MPGAA* | `delta_mpgaa` | Обратный индекс только достигнутых клеток; блокирующая клетка служит свидетелем для всей закрытой ветви |
| Policy-Mesh-MPGAA* | `policy_mpgaa` | Граф нескольких допустимых tight-продолжений; поиск цепочки до цели перед раскрытием |
| Контроль Selective | `selective_no_prune` | Та же верхняя граница и поиск, отключено отсечение ветвей |
| Контроль Selective | `selective_geom` | В оценке ветви используется исходная геометрическая эвристика; остальной поиск продолжает обучаться |

Общий `MeshIndex` компилирует **исходные упорядоченные трассы** примитивов без изменения клеток, направленности, идентификаторов или float-стоимостей. Верхняя граница Selective всегда соответствует допустимому пути; отсечённая ветвь остаётся неизвестной, а не запрещённой. Delta регистрирует зависимости всех исходящих переходов каждого обученного состояния, включая доминируемые префиксы поиска. Policy проверяет актуальную допустимость перехода и равенство `h(u) = c(u,v) + h(v)` при обходе. Перед использованием обученных оценок любой вариант полностью обрабатывает освобождения, снижая эвристику очередью MPGAA*.

## Сборка и проверки

Из корня этой копии репозитория:

```bash
make -C cpp/mpgaa_mesh -j2 all
make -C cpp/mpgaa_mesh test
make -C cpp/mpgaa_mesh sanitize
cpp/mpgaa_mesh/build/test_sanitize cpp/experiments/frozen/grid8_model.txt
cpp/mpgaa_mesh/build/test_sanitize cpp/experiments/frozen/car16_model.txt
```

`test.cpp` содержит отдельный Дейкстру с прямым чтением клеток: 1 080 динамических снимков двух моделей, 6 488 сравнений кандидатов и абляций, проверки масок коллизий и согласованности эвристики. Аудит не создаёт зависимостей и не меняет состояние планировщика. Дополнительно проверяются нулевой бюджет и продолжение после его увеличения. У Boundary проверяется совпадение числа раскрытий с прежним MPGAA*.

## Новый эксперимент

```bash
python cpp/mpgaa_mesh/run_all.py --output cpp/mpgaa_mesh/results/reproduction
python cpp/mpgaa_mesh/analyze.py --directory cpp/mpgaa_mesh/results/reproduction
python cpp/mpgaa_mesh/report.py --directory cpp/mpgaa_mesh/results/reproduction
```

Генерировать входы заново не нужно. `frozen/manifest.json` фиксирует хеши входов и измеряемых исходников; `prepare.py` отказывается заменять существующий манифест. `run_all.py` не компилирует код во время замеров и продолжает только полностью завершённые задания с теми же бинарниками и выходными хешами. Незавершённые данные сохраняются: для повторной попытки нужен новый каталог. Задания выполняются последовательно, сначала три повтора времени, затем один проход памяти на каждой конфигурации. При измерениях другие сборки и вычислительные проверки запускать не следует.

Основной набор:

- Все 186 прежних replay-сценариев: 90 car16 и 96 grid8.
- Все 40 прежних миссий раскрытия карты: два радиуса car16 и три grid8.
- Навигация с динамикой на всех 16 картах: два корня, четыре заранее выбранные точки `(k, cr) = (2,5), (8,10), (32,20), (64,30)`, `n=k`.
- Раскрытие неизвестной car16-карты: шесть карт, два корня, радиусы 16 и 64.

Это **подмножество четырёх опорных точек**, а не повтор полного перебора всех 36 k/cr. Старые времена в новые отношения не подмешиваются. На replay также измеряются две абляции Selective. Контроли: MPGAA*, MD-A*, LBA*, LBA* reuse, Boundary-Mesh; на grid8 добавлен усиленный Octile A* reuse.

Пример одного нового запуска:

```bash
cpp/mpgaa_mesh/build/replay --input cpp/experiments/frozen/car16_replay.txt \
  --output /tmp/mesh-mpgaa-example.csv --case history --repeats 3 \
  --methods mpgaa,boundary_mpgaa,selective_mpgaa,delta_mpgaa,policy_mpgaa
```

Для сокращённого нативного вызова указывайте методы явно. `octile_reuse` поддерживает только grid8 и автоматически исключается из стандартного набора на car16. CSV и JSON завершения не перезаписываются.

## Границы измерения и счётчики

`time_s` / `planner_s` включают применение изменений, уведомления, снижение эвристики, поиск, обучение, извлечение и сохранение пути. `setup_s` учитывает конструктор планировщика. Компиляция общих моделей, сенсор, независимый контроль и проверка пути выполняются вне таймера. Полный эпизод — конструктор плюс все вызовы; online — сумма вызовов после первого. Для собственных траекторий online сравнивается за весь эпизод, а не как одинаковые запросы.

Лимит 1 000 000 относится к раскрытиям одного запроса (для MD общий бюджет ядра); работа ремонта эвристики не имеет отдельного лимита. Лимиты, недостижимость и ограничения движения остаются в данных. В replay `no_path` — вычисленный ответ; в навигации достижение цели рассматривается отдельно от доказанного отсутствия пути по карте знаний.

Память — запрошенные C++ heap-байты отдельного инструментированного бинарника, не RSS. Сравниваются пик и живая память планировщика с результатом. Общие модели, стек, метаданные аллокатора и внешний валидатор исключены. В replay метаданные `variant_model_heap_*` учитывают совместную подготовку прежних mesh-моделей **и нового MeshIndex**; это отдельная общая стоимость. Времена инструментированного бинарника не используются для ускорений. Пути, статусы и счётчики его первого повтора сверяются с временным проходом.

К прежним счётчикам добавлены:

| Поле | Смысл |
| --- | --- |
| `mesh_nodes` | Посещённые клетки узлов префиксного дерева |
| `bound_evals` | Вычисленные `c(p)+h(end(p))` при оценке ветвей |
| `pruned_branches`, `pruned_primitives` | Отсечённые ветви и число содержащихся в них примитивов, с повторениями по раскрытиям |
| `watch_hits` | Доставленные ссылки из обратного индекса Delta |
| `validity_flips` | Изменения итоговой допустимости материализованных примитивов после пакета правок |
| `witness_stops` | Остановки обхода на препятствии или границе карты |
| `policy_probes` | Проверенные альтернативы tight-графа, включая повторную проверку кадра DFS |
| `policy_hits` | Успешные новые обходы tight-графа; это не число пропущенных полных поисков |
| `alternate_uses` | Выбор tight-перехода, отличного от текущего указателя `next` |

Нулевые специализированные счётчики другого метода не означают отсутствие любой работы. `certified` у Policy означает успешный ответ с нулём раскрытий; `backend_calls=1` учитывает обращение к общему решателю. Конкретные функции разных планировщиков не имеют одинаковой цены одного раскрытия.

`pruned_branches` может включать ветви с готовой маской и примитивы, которые всё равно отбросило бы сравнение g: это не число предотвращённых проверок коллизий. `alternate_uses` также включает установку отсутствующего next. `checked_cells` считает инструментированные проверки клеток трасс, включая отказ за границей; отдельные служебные проверки стартовой и целевой клеток в него не входят.

Численные сравнения принимают расхождение стоимости до `1e-6`; используются исходные double-стоимости и `EPS=1e-9`. Доказательства в отчёте сформулированы в точной арифметике. Экспериментальная реализация не устанавливает литературную новизну алгоритмов.

## Перенос

Ветку из прилагаемого bundle можно клонировать командой `git clone -b research/mpgaa-mesh-four /path/to/introduction-mpgaa-mesh.bundle target`. В свежем клоне `python cpp/mpgaa_mesh/validate_artifact.py` собирает четыре экспериментальных бинарника, сверяет их байты с измеренными, повторяет независимые проверки и воспроизводит таблицы из сохранённых данных. Сам валидатор не выполняет новых временных замеров. Для исполнения компактного ноутбука: `python cpp/mpgaa_mesh/notebook.py`.

Первый остановленный проход сохранён в `results/pre_memory_accounting_fix`, вместе с исходниками и манифестом. В нём обнаружена ошибка старого mission-учёта памяти; исправленный стенд считает живую память между вызовами, замену ответа и пик конструктора. Вся основная серия измеряется заново; данные первого прохода исключены.

Перед отдельным проходом памяти была исправлена ещё одна ошибка диагностики: длинный строковый аргумент `require()` мог выделить память до вычисления выражения с глобальным счётчиком. Снимок счётчика теперь вычисляется заранее. Изменение находится под `IMA_TRACK_ALLOC`; SHA-256 обоих обычных бинарников остались прежними. Поэтому 29 завершённых временных заданий импортированы побайтно, а профиль памяти начат заново. Исходник до исправления, манифест, состояние и прерванный профиль сохранены в `results/pre_instrument_argument_fix`. `allocation_revision` в новом манифесте и `imported_timing` в состоянии фиксируют эту связь; `resume_allocation.py` — одноразовая проверенная процедура восстановления, её не следует повторять. Новый контроль миссии сверил 229 строк. Предварительные остановленные профили не участвуют в анализе.

В эпизодных таблицах `retained_heap_bytes` означает живую память после последнего зарегистрированного запроса, а `peak_heap_bytes` — максимум за эпизод, включая конструктор и возвращённый путь. `finish.py --wait` ждёт измерения, строит отчёт и исполняет notebook; для отдельного Python-окружения notebook задайте `MPGAA_NOTEBOOK_PYTHON`. Тесты и анализ не запускаются одновременно с временными замерами.
